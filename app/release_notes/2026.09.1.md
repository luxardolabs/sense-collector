# 2026.09.1 — 2026-09-16

Fixes a bug that could silently stop your collector from recording anything. Upgrading is strongly recommended. The way you start the stacks has changed — see Before you upgrade.

## FIXED

- **The collector could stop recording and never recover** `Collector` — When its login to Sense expired, the realtime connection was refused and the collector kept retrying with the expired login forever. It looked fine — still running, still fetching your device list — but no power readings were being recorded at all. It now logs in again and reconnects on its own. Both of our own collectors had been in this state since mid-July before we found it.
- **A collector that cannot log in now stops instead of pretending** `Collector` — If logging in keeps failing, the collector exits so your container restarts and the problem is visible, rather than sitting there quietly doing nothing. A brief outage at Sense's end is still ridden out, not treated as fatal.
- **Startup could fail against a renamed database service** `Deployment` — The dev stack could come up pointing at a database address that no longer existed. Each stack now names its own.

## CHANGED

- **Each Sense monitor now has its own named stack** `Deployment` — If you run more than one monitor, each gets its own collector, database, dashboards and port, so they no longer collide. Ours are `dev-tyle` and `dev-bb`.
- **One compose file instead of five** `Deployment` — The separate dev/demo/prod/e2e files are gone; the same stacks are now profiles of a single `compose.yaml`. `make dev-up`, `make demo-up` and `make test-e2e` work as before.
- **The bundled database no longer takes a port on your machine** `Deployment` — It was never needed, and it clashed with other services. Only Grafana is published now.

## IMPROVED

- **Reliability** `Collector` — Behind-the-scenes work on the test suite and automated checks. Nothing to do; the collector should simply be steadier.

## Before you upgrade

This release is a drop-in for the collector itself — nothing to change in your settings, your database or your dashboards, and nothing to migrate. **But the stacks are started differently now**, so if you drive them by hand:

- `docker compose -f compose.dev.yml up` no longer works. Use `make dev-up`, or `docker compose --profile dev-tyle --env-file .env.dev-tyle up`.
- Container names changed (for example `sense-collector` is now `sense_dev_tyle_collector`). Anything you have scripted against the old names needs updating.
- **If you were running a bundled stack, its stored data lives under the old names.** We moved ours across and verified nothing was lost; a fresh start on the new names begins empty, so move yours before you switch if you want to keep the history.

Still not supported: Sense accounts with multi-factor authentication enabled. Tracked as issue [#8](https://github.com/luxardolabs/sense-collector/issues/8).

Surfaces used above: `Collector` (the running collector — what it reads, writes and logs) and `Deployment` (the image and the stacks you run to operate it).
