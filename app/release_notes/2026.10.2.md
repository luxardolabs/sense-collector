# 2026.10.2 — 2026-10-10

A security update for 2026.10.1. Upgrade if you run 2026.10.1, especially with debug logging turned on.

## FIXED

- **Your Sense login token no longer appears in debug logs** `Collector` — With debug logging turned on, 2026.10.1 could write the temporary token the collector uses to talk to Sense into its log. The token is now hidden at every log level. Normal logging was never affected.
- **Device names can no longer fake log lines** `Collector` — A device name containing special characters could make the readable (text) log format show a fake line. The default JSON format was never affected.
- **Every published image is fully checked** `Deployment` — The ARM image in 2026.10.1 was published without its vulnerability scan. It has since been scanned and is clean. From this release on, every architecture is scanned before anything is published.
- **A cleaner image** `Deployment` — Removed a few leftover development files that had slipped into the image.

______________________________________________________________________

## Before you upgrade

Nothing to do. No settings, database or dashboard changes. Pull the new image and restart.

If you ran 2026.10.1 with `LOG_LEVEL=DEBUG`, treat your logs from that period as containing your Sense session token.

Still not supported: Sense accounts with multi-factor authentication enabled. Tracked as issue [#8](https://github.com/luxardolabs/sense-collector/issues/8).

Surfaces used above: `Collector` (the running collector — what it reads, writes and logs) and `Deployment` (the image and the stacks you run to operate it).
