# 2026.10.1 — 2026-10-10

A maintenance update. The collector now writes its logs as structured JSON, and a security fix lands in one of its network components. Read "Before you upgrade" if you use file logging or parse the log output.

## CHANGED

- **Logs are now JSON, one line per event** `Collector` — Every log line is a single JSON object with the time, level, message and any details. Log tools can search and filter it directly. For plain readable lines while developing locally, set `LOG_FORMAT=text`.
- **Logs go to the container output only** `Collector` — The option to also write log files is gone. Read logs with `docker logs`, or collect them with your usual log tooling.

## FIXED

- **Security fix in a network component** `Collector` — Updated a library the collector uses to talk to your database, closing a published vulnerability.

## IMPROVED

- **Safer releases** `Deployment` — Every published image is now scanned for known vulnerabilities before it is released, and a released version can never be overwritten.
- **Reliability** `Collector` — The automated tests now write to and read from a real database, not a simulated one.

## Before you upgrade

- If your settings include `SENSE_COLLECTOR_STRUCTURED_LOGS`, `SENSE_COLLECTOR_LOG_DIR`, `SENSE_COLLECTOR_LOG_FILE_MAX_BYTES` or `SENSE_COLLECTOR_LOG_FILE_BACKUP_COUNT`, you can delete them. They no longer do anything.
- If anything reads the collector's console output, expect JSON lines from now on.
- The per-area log levels (`SENSE_COLLECTOR_LOG_LEVEL_GENERAL`, `_API`, `_STORAGE`) work as before.

No database or dashboard changes, and nothing to migrate. Pull the new image and restart.

Still not supported: Sense accounts with multi-factor authentication enabled. Tracked as issue [#8](https://github.com/luxardolabs/sense-collector/issues/8).

Surfaces used above: `Collector` (the running collector — what it reads, writes and logs) and `Deployment` (the image and the stacks you run to operate it).
