# 2026.10.1 — 2026-10-10

A guard-alignment release. The guards move to luxarch 0.277.0 / luxlint 0.63.1 / luxaudit 0.13.2, and the 14 new reds plus one CVE are fixed by aligning to the standards they enforce. Two operator-visible changes: logs are JSON on stdout by default, and file logging is gone. No data-shape change; no migrations.

Still open, did **not** ship: **SENSECOLLE-35** (MFA/TOTP auth, GitHub issue #8). Triaged this window; nothing implemented.

## Features

None. No new collector capability.

## Refactors

- **Logging is the fleet module** (`repo.logging_canonical`). `app/core/logging_config.py` (`luxarch --emit logging`, never hand-edited) is installed once in `app/main.py` via `configure_logging(service="sense-collector", version=…, levels=AREA_LEVELS)`. `app/utils/logging.py` keeps only the three per-area loggers (`general`, `api`, `storage`) and their levels; httpx/httpcore are held at WARNING. Removed: `StructuredFormatter`, `ColoredFormatter`, the `setLogRecordFactory`-based `LogContext`, and the rotating file handler. Device names stay injection-safe: the JSON formatter escapes control characters, which replaces the old `_neutralize`.
- **`make test` is the emitted luxarch test block** (`repo.test_block_wired`, `repo.test_stack_parity`). It builds the Dockerfile's new `test` stage (`make test-build`) and starts a real `influxdb:2.7` in a per-run compose project (profile `test`, service `sense_test_influxdb`, tmpfs only). It measures branch coverage with coverage.py and keeps both exit codes. `Dockerfile.test` and its stamp are retired; `pytest-cov` is replaced by `coverage`.

## Schema / Migrations

None — this collector has no relational data layer. InfluxDB measurements are unchanged.

## Infra / Ops

- **Release path guarded** (`repo.deploy_tag_is_immutable`, `repo.release_scans_candidate`, `repo.github_release_wired`). `version-build-push`, `release` and `release-public` refuse an already-released tag (fail-closed: only the registry's not-found answer counts as unreleased) and a dirty tree. Each scans the exact image it will publish with `luxaudit --image-archive` before pushing. `release` builds multi-arch to a `candidate-<commit>` tag, then pulls and scans it before `imagetools create` points `:VERSION`, `:sha-<commit>` and `:latest` at that digest. It finishes with `make gh-release` (renamed from `github-release`, with a gh/notes/remote-tag preflight).
- **InfluxDB config path no longer on an anonymous volume** (`repo.compose_db_ephemeral_volume`). `/etc/influxdb2` is a named volume on dev-tyle, dev-bb and demo (`sense_*_influxdb_config`), and tmpfs on e2e and test.
- **Guard pins: luxarch 0.249.1 → 0.277.0, luxlint 0.60.1 → 0.63.1, luxaudit 0.12.0 → 0.13.2.** The 0.276.0 bump carried the burn-down below. 0.277.0 / 0.63.1, published during the release, needed only release-skill v7 (where each tag goes: `RELEASE_REGISTRY`, which defaults to `REGISTRY`, so nothing changes here), fleet-start-skill v4, and a re-emit of the hooks (new `fleet-start-after-compact`).
  - Re-emitted assets: wrap-up v7, escalate v3, release v6 and pin-bump v2 skills, plus three new skills (fleet-start, luxpm-audit, adversarial); claude-pointer v7, changelog-guide v2, guard-upgrade v1 and gitleaks v12; the Claude Code hooks and the luxlint git hooks.
  - guard-upgrade and gitleaks carried local edits outside their editable regions (`$(LUXARCH_REGISTRY)` for `$(REGISTRY)`, and a no-registry skip). The edits were undone so the assets match their released text.
  - gitleaks v12 rescans files git treats as binary, and its identity allowlist admits only the fleet noreply.
- **multidict 6.7.1 → 6.9.1** (CVE-2026-104874, a reference leak reachable by a remote client). Transitive under aiohttp; nothing else in the lock moved.
- **LuxPM backlog:** 15 historical closes got their missing summaries, and SENSECOLLE-35 was triaged (`repo.luxpm_backlog_triaged`).

## Fixes

- None to collector behaviour. Two tests in `test_main.py` that checked secret masking would have passed on an empty capture once `general` stopped setting its own level. They now pin the capture level explicitly.

## Notes

**Pre-deploy:** if anything parses the collector's console output, switch it to JSON lines (one object per line; caller fields under `attributes`). For readable output in local development, set `LOG_FORMAT=text`.

**Post-deploy:** remove these settings from your `.env.*` files. They are now ignored, and the collector has no file log any more:

- `SENSE_COLLECTOR_STRUCTURED_LOGS`
- `SENSE_COLLECTOR_LOG_DIR`
- `SENSE_COLLECTOR_LOG_FILE_MAX_BYTES`
- `SENSE_COLLECTOR_LOG_FILE_BACKUP_COUNT`

Read logs with `docker logs` or your log driver. The dev and demo stacks gain one named volume each for InfluxDB's config path, created on the next `up`.

New runtime knobs from the logging module: `LOG_LEVEL` (root level), `LOG_MODULE_LEVELS` (per-logger JSON overrides, e.g. `{"api": "DEBUG"}`) and `LOG_FORMAT`.
