## Features

- **MFA login (SENSECOLLE-35).** `SENSE_COLLECTOR_MFA_SECRET` (optional, base32) — a 401 + `mfa_token` from `/authenticate` is completed at `/authenticate/mfa` with form `totp` (pyotp 2.10.0), `mfa_token`, `client_time` (`%Y-%m-%dT%H:%M:%SZ`, UTC). First login, renewal and WS re-auth all go through it. No secret on an MFA account: `SenseMFAError` naming the setting (a renewal backs off as on any failed login). The secret is normalized (case, every kind of whitespace, zero-width characters; only ASCII is upper-cased), masked in the startup log (`SECRET` added to the sensitive markers), and refused at startup unless base32. Protocol per sense_energy's `validate_mfa`.
- **Fake Sense MFA mode.** `SENSE_FAKE_MFA_SECRET`: `/authenticate` answers 401 + `mfa_token`; `/authenticate/mfa` checks its own RFC 6238 TOTP (±1 step, checked against the RFC vectors), `mfa_token`, and `client_time` format within 60 s.

## Fixes

- WS auth-failure limit: `RuntimeError` from `_refresh_credentials` was caught by `run()`'s last-resort `except Exception`, so the process never exited (SENSECOLLE-114). Any non-401/403 connect failure (InvalidMessage included, by owner decision) now resets the run.
- WS URL token percent-encoded for `&`, `#`, `%`, whitespace, non-ASCII; tokens that work raw are sent byte for byte (SENSECOLLE-106).
- `_BEARER` redaction in every log field, tracebacks included (SENSECOLLE-109).
- Realtime epoch: ±inf / 1e20 / NaN / bool / string no longer raise out of storage or write a 1970 point; floats are whole seconds (SENSECOLLE-107).
- `convert_to_epoch` accepts `…Z` with or without a fraction and explicit offsets; a date-only or zone-less value is still None (SENSECOLLE-102).
- `collect_sense_data` teardown awaits both periodic tasks and lets an outer cancel propagate (SENSECOLLE-120).
