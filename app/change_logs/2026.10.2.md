# 2026.10.2 — 2026-10-10

A security fix release for 2026.10.1. An independent adversarial review of 2026.10.1 found five problems; all are fixed here. The one with real reach: at `LOG_LEVEL=DEBUG`, 2026.10.1 writes the live Sense WebSocket access token to the log. No config, data-shape or dashboard changes; no migrations.

## Issues Closed

- **SENSECOLLE-50** — /adversarial findings on 2026.10.1: the WebSocket token logged at DEBUG, log forging in `LOG_FORMAT=text`, arm64 published unscanned, host `.pyc`/`.DS_Store` files baked into the image, and `refuse_released` trusting any HTTP 404. Each was reproduced with a control and seen failing before its fix. (f9fccd4)

Still open, did **not** ship: **SENSECOLLE-35** (MFA/TOTP auth, GitHub issue #8).

## Infra / Ops

- **`publish_scanned`** replaces the tag-based scan in `release` and `release-public`. It reads the candidate's index digest once and scans every platform image in it, each pulled by its own manifest digest. Only then does `imagetools create` publish from that pinned digest. 2026.10.1 pulled by tag, which fetched only the host's amd64 image, so arm64 shipped unscanned. Scanning by tag also left a retag race between scan and publish. A dry run against the 2026.10.1 index scanned amd64 `3ae75e15…` and arm64 `68d8dd1a…` (0 fixable each), and a failing scan exits before anything is published.
- **`refuse_released` requires a real registry.** A not-found counts only when the host's `/v2/` answers with `Docker-Distribution-API-Version`. A plain web server's 404 (a wrong port, a misrouted proxy) used to read as "unreleased" and now refuses. Controls: an unreleased version on the private registry and on GHCR still proceeds, and a released tag still refuses.
- **`.dockerignore` cache/OS patterns are `**/`-recursive.** The bare patterns matched only at the context root, so `COPY app` baked host `__pycache__` and `.DS_Store` into the image: 17 files in 2026.10.1, 0 now.

## Fixes

- **The WebSocket access token is never logged.** Sense requires the token in the realtime URL (SENSECOLLE-21), and websockets logs that request line at DEBUG. `app/core/privacy.py`'s redactor, passed as `configure_logging(redact=...)`, replaces it with `[REDACTED]` at any `LOG_LEVEL` and under any `LOG_MODULE_LEVELS` override. `tests/test_privacy.py::test_the_ws_access_token_is_never_logged[DEBUG]` failed with the redactor removed.
- **Device names cannot forge log lines in text mode.** The same redactor escapes control characters in every caller-visible field. Tracebacks keep their newlines and lose only a token. This restores SENSECOLLE-20's protection under `LOG_FORMAT=text`; JSON was already safe. `test_a_remote_device_name_cannot_forge_a_line_or_emit_escapes[text]` failed with the redactor removed.
