# 2026.09.1 — 2026-09-16

A reliability release. One real outage fixed, the run stacks restructured, and the guards brought forward 48 releases. No config or data-shape changes; no migrations.

## Issues Closed

- **SENSECOLLE-44** — Collector never recovers from a WebSocket 401. The access token is a query parameter in the WS URL, and that URL was built once at startup and never re-derived, so an expired token meant every reconnect re-presented a dead credential. Fixed in 4c14bb4; ratification found and fixed a second defect in 860ff16 (see Fixes).
- **SENSECOLLE-21** — re-closed as a **correction**. Its original conclusion ("the `Authorization` header is redundant with the URL token") was wrong and caused SENSECOLLE-44. Recorded in 7020b27 along with a warning at the code site.

Opened and cancelled in this window, recorded so the board is not confusing: **SENSECOLLE-42** and **SENSECOLLE-43** were tickets I opened for guard *reds*. `--playbook burn-down-order` is explicit that reds are the sweep and are tracked by the guard itself — *"you don't ticket each relay, you just fix and commit"* — so both were cancelled. Tickets are for findings.

Still open, did **not** ship: **SENSECOLLE-35** (MFA/TOTP auth) — the only external ask, GitHub issue #8, open since 2024. Verified absent from this window.

## Refactors

- **Run stacks modelled as a 2×2: {dev, prod} × {tyle, bb}.** The house has two Sense monitors, so there are four real-account stacks — `dev-tyle`, `dev-bb`, `prod-tyle`, `prod-bb` — plus `demo` and `e2e`. Each has its own service names, container names, volumes and Grafana port, so any combination runs side by side. (e3eab46)
- **Five compose files collapsed into one `compose.yaml` using profiles** (`compose.yml`, `.dev`, `.demo`, `.e2e`, `.prod` are gone). luxarch 0.159.0 made any file that is not `compose.yaml` a violation, on the owner directive *"I just want one way known"*. A service carrying a `profiles:` key is inert unless that profile is named, which is what makes one file sufficient. (4c14bb4)
- **Compose no longer builds anything.** The fake-Sense emulator is built by a new `make harness-build` into `sense-collector-fake:local` and referenced by tag, per `--playbook compose-hygiene`: *"a fake-device harness is built outside compose too, then run by tag. There is no test/demo/e2e exemption."*

## Fixes

- **A WebSocket auth rejection no longer strands the collector.** `connect()` catches `InvalidStatus` **before** `WebSocketException` (it is a subclass, so order decides which handler wins) and counts 401/403 as an auth rejection rather than transport noise. `run()` then re-authenticates and **rebuilds the URL**, so the next attempt carries a live token. After `SENSE_COLLECTOR_WS_AUTH_FAILURE_LIMIT` (default 5) consecutive rejections the credential is treated as wrong rather than stale: the process exits and the restart policy surfaces it, instead of the collector idling with no data. (4c14bb4)
- **A transient re-authentication failure is tolerated.** `authenticate()` re-raises, so the first version would have exited on the very first blip from Sense's auth endpoint, never reaching the limit — both a regression against the old retry-forever behaviour and the opposite of the stated intent. The failed refresh is now caught and counted; the limit is what converts a *persistent* failure into an exit. (860ff16)
- **The dev profile pointed at a stale InfluxDB hostname.** `.env.demo` still named `sense_influxdb` after the services were renamed; demo overrode it in compose but dev did not, so dev would have started against a host that no longer exists. Each profile now sets its own URL. (f9947ad)
- `scripts/e2e-test.sh` referenced the pre-rename e2e service names — caught by running it, not by reading it. (e3eab46)

## Notes

**Pre-deploy:** none. **Post-deploy:** none for the collector itself — no config, env-var or data-shape change, and no migration.

**But the run stacks changed shape, and that is not automatic:**

- `docker compose -f compose.dev.yml …` no longer works; use `make dev-up` / `make bb-up`, or `docker compose --profile dev-tyle --env-file .env.dev-tyle …`.
- Container names changed (`sense-collector` → `sense_dev_tyle_collector`, etc.). Anything scripted against the old names needs updating.
- Credentials now live in a gitignored `.env.<stack>` per stack. `.env.dev-tyle` and `.env.dev-bb` exist on this host; `.env.prod-tyle` / `.env.prod-bb` are not yet configured.
- **Volumes were migrated, not recreated**, and every copy verified by checksumming the whole tree before and after: dev-tyle 1,018,950 and dev-bb 1,297,767 `sense_mains` points intact. A fresh `up` on the new names would otherwise have started empty.

**Field note.** Both live collectors had been stalled since mid-July — ~85,000 WS rejections each over two months — while REST kept polling and the collectors looked alive. The heartbeat healthcheck did report `unhealthy` the whole time; nobody acted on it. Detection was never the gap. Both are now on this build and collecting.

## Known reds

- **`repo.release_tag_hygiene`** (2 findings) — our tags are bare (`2026.8.0`, `2026.09.0`); the fleet standardised on `v<VERSION>`. **This release resolves it**: it is the first tagged `v2026.09.1`, and the rule only flags a bare tag newer than the newest `v`-tag. The remedy is explicit that existing tags are immutable history to leave alone — *"Retagging and deleting a published tag is a history rewrite on a remote others may have fetched: that is the owner's call, never a remediation step, and this rule does not ask for it."* Not deferred, not allowlisted; it clears the moment this release's tag lands.

`repo.release_docs_present` and `repo.release_docs_current` are both genuinely green.
